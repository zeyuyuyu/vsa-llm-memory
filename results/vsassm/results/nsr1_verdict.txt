5-hop chain specimen > CB-013 > R-07 > CB-007 > R-05 > FRZ-05. The graph query follows any length and adds 5 specimens

fact: an engine-side check on reader output, noted for NSR2.

- 166 arm-3 (32B) misses: 46 missed items, 39 other wrong sets, 33 no answer (limit hit and the forced answer still

  misses found one FORMAT failure: on home the model writes IDs as in the camera log ("reading_glasses"), which the
  registered parser does not map to "reading glasses".
- Question-wording defect (mine): "Which of Grandpa's things have to be moved out of it?" is read by the LLM as "items
  that belong to Grandpa" (its own reasoning says so: "the items that are specifically referred to as Grandpa's are the
  reading glasses and the slippers"), while the gold counts every tracked item. It affects only the LLM arms and only the
  80 home questions; arms 1/2/4 use the question type, not its wording.

- Underscore-normalising parse (all LLM arms): 32B 0.278 -> 0.304 (home 0.288 -> 0.363); 8B 0.148 -> 0.113 (its old
  credit came from unparsed items on empty-answer questions); 3b unchanged 0.826.

- Excluding the 80 ambiguous home questions (150 left): arm 1 0.907, 32B over the log 0.273, 32B over the RM state 0.887,
  graph query on the RM state 0.907. With the state given, the LLM composes almost as well as the query (-0.02); its
  -0.63 over the log is state tracking.
- Cross-engine: 12 problems answered by both HF generate and vLLM (identical prompts, 6,951-7,321 tokens): same parsed
  answer on 3/12; correct 6/12 (HF) vs 2/12 (vLLM). Long greedy reasoning chains diverge under different numerics, so
  per-question LLM answers are unstable; the aggregate gap is far larger than this noise.
- Reader reproducibility: home/ops re-read on another GPU in another batch: 3/4,600 per-line events differ, final state
  identical 20/20.

## Conclusion
On fresh logs, a continuously tracked readable state composed with site facts answers impact questions at 0.93
set-exact, against 0.28-0.30 for Qwen3-32B thinking over the same log with the same assets and facts, 0.15 for Qwen3-8B,
and 0.31 for the system of record. Every arm-1 miss is a misread state fact; the composition engine never erred, and the
VSA rule memory, a count table and a hand-written graph query give the same answers (230/230 and 229/230). Given the
state as text, Qwen3-32B composes almost as well as the query on unambiguous questions, so the LLM's deficit is state
tracking over a long, overwritten, multi-channel log, not composition.
Supports: "reading a continuously updated state from messy logs, then composing it exactly, answers impact questions
that an LLM reading the log misses." Does not support: "VSA reasons" (NSR0, P4); claims about frontier long-context
models (not tested); claims beyond these four simulated sites (LLM-written human lines from a simulator, one generation
seed per log, Qwen3-32B both wrote the human lines and is a baseline; the reader was distilled on similar generator text,
the LLMs are zero-shot).

## Literature check (conclusion -> literature)
SUPPORTED: end-to-end LLMs degrade on state tracking with overwrites and indirect effects (ActionReasoningBench: GPT-4o
state tracking 73-76%, ramification 0%, Tables 3-4, re-opened; PI-LLM: accuracy falls toward zero with overwrites);
memory systems fail impact questions over changing state (MEME: Cascade 3% on average, abstract re-opened). CONFLICTS
(partially): long-context GPT-5-mini beat a Mem0 fact memory on recall (arXiv 2603.04814, abstract re-opened); the setups
differ (single-fact recall vs set-valued impact questions over overwritten multi-channel state), but a frontier
long-context arm is the strongest baseline we have not run. NO PRECEDENT FOUND for the exact stream setting
(docs/neurosymbolic_review.md Part III).

**P2-F (arm 1 - frontier >= 0.20): FAIL** (+0.013; 95% bootstrap interval -0.030 to +0.057, a statistical tie).
**My prediction (frontier about 0.55, range 0.45-0.70) was wrong**: the frontier model reading the whole ~10k-token log
answers impact questions as well as the tracked state does.
Errors are mostly disjoint: both right 198, only RM 16, only frontier 13, both wrong 3; "either right" 0.987.
**Revised conclusion.** "An LLM reading the log misses impact questions" holds for the open models tested (Qwen3-32B
0.28, Qwen3-8B 0.15), NOT for a frontier model at this log length. What still separates the pipeline at this scale:
cost and latency (the frontier model spends $0.017 and 39 s per question and re-reads the log for every question; the
pipeline reads each message once with a 1.7B model and answers in ~0.3 ms with no generated tokens), on-device
operation, and traceable answers. Open: whether the frontier model holds up as logs grow (more days, more items,
more overwrites; PI-LLM reports long-context accuracy falling toward zero with overwrites), and whether the two
complementary error sets can be exploited (the pipeline as the always-on state, the frontier model as an auditor).
This sharpens the literature CONFLICT recorded above (2603.04814: long-context GPT-5-mini beat a fact memory on recall):
it is now confirmed in our own setting for a frontier model.
