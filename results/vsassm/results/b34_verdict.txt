## Reading (written by hand after the generated part; the reading rules are in the prereg)

Setting. Every stored bit of every arm is a differential pair of PCM cells on B25's device model; the tables keep their
key directory (CAM words, hash displacements, last-value flags) on the same cells; every arm uses at most the VSA
store's cell count C = S x 8,192 (cells used: 97-100% of C for every table arm except T-iih, 51-100%, whose integer
repetition leaves cells unused on some stores); queries are the 4,776 probed keys.

1. H1, primary (V-S, the store read as published, threshold 0.5): TABLE WIN at every time. The table that finds a row
   through a stored minimal perfect hash (T-v: 15-16-bit displacements per bucket of about 5 pairs, i.e. 3.0-3.2 bits
   per pair on the largest stores, with every bit repetition-coded 29-30 times) reads 100 / 100 / 91.69 / 18.80% at x4 / x8 / x16 / x32 (30 days)
   against the store's 100 / 98.60 / 0.15 / 0. Moving the directory onto the devices costs the best table 7 points at
   x16 (B26b's digital-directory table T-iv: 98.79) because a hash directory needs bits, not keys. The B26b sentence
   holds in the fully in-memory setting.
2. The user-named key CAMs lose to the VSA store at moderate noise, as the reading rule anticipated. Exact matching of
   the native key bytes (T-i) fails at x4 (1.49%; hand-read: 1-7 of 225-233 word cells flipped, exact match needs 0),
   as does majority matching with only r = 2 copies (T-iih, 2.72%). Nearest-Hamming matching of the native code
   (T-iis) reads 98.99 / 89.97% at x4 / x8 against 100 / 98.60 (V-S ahead by +8.63 [+5.97, +11.54] at x8): keys that
   share the adjective differ in a few bits (hand-read: 'roasted-air' -> 'roasted-car', 2 bits apart; 'hot-box' ->
   'hot-fob', 4 bits). Registered reading: the VSA store beats a CAM that holds the keys, not a table: a hashed
   directory (T-iix, T-v) does not store keys and matches the store at x8 (99.77, 100).
3. H2 (V-Snt, the same device reads with the first value taken by argmax, the tables' own "key present" assumption):
   VSA WIN (not strict) at every time: ties at x4 and x8, +7.08 [+5.24, +8.70] at x16 and +60.62 [+56.90, +63.31] at
   x32 over T-v (V-Snt 100 / 100 / 98.76 / 79.42). So V-S's collapse at x16 is its fixed threshold, not its code
   (hand-read: at x16 the true value is still the best candidate, at similarity 0.31-0.41 against a 0.5 threshold;
   the best similarity at the next, empty position is 0.16-0.19). V-Snt's remaining x16 losses are exactly the 57 probed keys that hold more
   than one value (27 in vt, 30 in multivalue; all lost at x16 and x32), because its stop rule after the first value
   still needs the threshold (hand-read: later-value similarities 0.31-0.48, all the best candidate); on those small stores the hashed table is
   better (multivalue 100 vs 83.1, vt 100 vs 72.7 at x16).
4. H4 (which ingredient): with V-S, TABLE WIN; with V-Snt, TABLE WIN at 30 days (TIE at 1 year). The table whose
   every field is a random high-dimensional code decoded by similarity, with no superposition and no stored key
   (T-vhdd), reads 100 / 100 / 100 / 84.99%: ahead of V-Snt by +1.24 [+0.70, +2.06] at x16 and +5.57 [+3.89, +7.28] at
   x32. Partly high-dimensional tables fall in between: high-dimensional values with a repetition-coded hash directory
   (T-vhd) 100 / 59.92, high-dimensional keys and values searched over all rows (T-iiib) 99.94 / 51.32, high-dimensional
   keys with repetition-coded values (T-iiia) 90.24 / 21.11 at x16 / x32. The robustness at high noise therefore belongs
   to random high-dimensional codes with similarity decoding in every field (the VSA ingredient), which a table can use
   as well; superposition adds none on top. What the store gains over a key-holding table is that it stores no
   per-pair address, which a hashed table also achieves.
5. H3 (V-SC, the store and its clean-up codebook both on the devices: the fully in-memory VSA): TABLE WIN. V-SC fails
   at x8 (0.27%; B25's GDC gain bias on the codebook crossbar), V-SCnt at x16 (0.75%). Its codebook costs N_values / S
   (about 16) times the store's cells; tables given the same total device count read 100% (T-v@tot) and 99.58%
   (T-iix@tot) at x32. Even at the store's budget alone (H3c) every non-HD table beats it from x8 on.
6. At the measured device parameters (x1) every arm reads every key at every time (G0); at x2, only the unprotected
   exact-match CAMs lose keys (T-i 96.8%, T-iih 96.4% at 30 days). Everything above is about stressed devices (every
   noise source multiplied 4- to 32-fold).

Limits. A simulation of one published PCM model (Joshi et al. 2020; fitted to 1e5 s, so 30 days and 1 year are
extrapolations) with i.i.d. cell errors: no spatial correlation, stuck cells or temperature, which would hurt
repetition copies placed together and are what Karunaratne et al. counter by spreading each hypervector across the
array. Only storage cells are counted: CAM match-line circuitry, majority gates, hash logic, ADCs and the digital
clean-up of V-S (the vocabulary's codes regenerated from strings) are not, so this is not an area or energy comparison.
No arm is scored on rejecting a key that is not stored: T-v and V-Snt cannot reject one, V-S can. T-iix, T-v, T-vhd and
T-vhdd were added by us (T-vhd and T-vhdd during the dev stage, after seeing dev results); every split and lambda was
chosen on synthetic dev stores, whose results the test reproduced within a few points in every cell.

What the paper can say (numbers from this file; 30 days; shares of the 4,776 probed RULER keys):
- "With every stored bit, including a table's directory, on the same simulated phase-change devices and at the store's
  device count, a table that finds its rows through a stored minimal perfect hash (about 3 directory bits per pair,
  repetition-coded) remains more robust than the VSA store read with its fixed acceptance threshold: 100%, 91.7% and
  18.8% of keys at 8-, 16- and 32-fold device noise against 98.6%, 0.15% and 0%. Tables that keep the keys themselves
  in a content-addressable memory do worse than the store (exact match 1.5% at 4-fold noise; nearest-Hamming match
  90.0% vs 98.6% at 8-fold)."
- "The store's collapse is its threshold, not its code: accepting the first value by argmax, as the tables accept their
  nearest row, the same reads give 98.8% at 16-fold and 79.4% at 32-fold noise, ahead of every table without
  high-dimensional codes (+7.1 [5.2, 8.7] and +60.6 [56.9, 63.3] points). A table whose fields are themselves random
  high-dimensional codes decoded by similarity, without superposition, does as well or better (100% and 85.0%). The
  robustness belongs to random high-dimensional codes with similarity decoding, which a table can use too."
- Must not say: that the vector form is more robust than a table at equal devices (H1 TABLE WIN; H4 TABLE WIN), or
  that superposition contributes robustness; nor "first" (no precedent found, results/b34_literature.txt).
