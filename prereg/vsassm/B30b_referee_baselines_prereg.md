# B30b pre-registration: two baselines a referee says favour our system (Qwen3-32B decoding on the logs; a notepad arm on BABILong)

Date: 2026-11-18 (box clock, Asia/Shanghai; US Eastern 2026-11-17 evening). Written, with all B30b code, before any
B30b test run: no B30b model has read a test log, a test question or a BABILong test sample. What ran before this file
is listed under "Development record" (CPU rescoring of banked outputs, dev logs, the BABILong training split, and a
sentence count of the test inputs with no model).

## Why

A strict referee of the npj Unconventional Computing manuscript says two baselines favour our system.

(a) **Operational logs.** Qwen3-32B, the paper's main larger-model baseline reading the whole log (Table 1: location
0.543, impact 0.278, window 0.202, against our 0.959 / 0.930 / 0.874), was run in thinking mode with *greedy* decoding,
an 8,192-token cap on reasoning plus answer, and budget-forced answers (apps/real/README.md; NSR1 amendment 2;
NSR3). Qwen3's model card asks for temperature 0.6, top-p 0.95, top-k 20 in thinking mode, warns that greedy decoding
"can lead to performance degradation and endless repetitions", and recommends an output length of 32,768 tokens. The
published runs hit the 8,192-token limit on 21 / 48 / 73 of the 414 / 230 / 460 questions.

(b) **BABILong.** The paper's "same 1.7B without the memory" baseline (B23: Qwen3-1.7B fine-tuned end to end; ours
+5.2 points at 128k, P = 2e-7) removes chunked reading, the event schema, the rules and the memory at once. The
referee asks for the analogue of RULER's facts-in-prompt arm (our B24 arm F): the same chunked reader writes the same
events, the events are given to a model as text lines (a notepad), and the model answers from the notepad instead of
the memory.

The result of both parts goes into the paper whatever it shows.

  committed, regenerated by that command).

- **Parsers and scorers (verbatim copies in `b30b_frozen/`, md5 below).** Location: `run_real.resolve_answer` +

### Changed (the referee's point): arm S32
- **Decoding:** Qwen3's thinking-mode recommendation, which is also the snapshot's generation_config.json:
  temperature 0.6, top-p 0.95, top-k 20, min-p 0, no presence penalty. One sample per question per replicate;
  per-request seed = replicate seed + 7919 x (position of the prompt in the prompt file).
- **Reasoning budget: 32,768 tokens** (Qwen's recommended output length). Pass 1 generates at most 32,768 tokens.
  - A run that ends (end-of-turn) is final.
  - A run that closed `</think>` within the budget but was cut inside its answer is continued (same sampling, up to
    4,096 more tokens): the budget limits reasoning, not the answer.
  - A run whose reasoning did not close within 32,768 tokens is budget-forced exactly as published: its own
    reasoning back, the CLOSE phrase of apps/real/force_answer.py, and up to 512 tokens to answer (the impact /
    window forcing budget of NSR1 amendment 2; for location this is more than the published 64, i.e. more lenient),
    same sampling.
- **Engine:** vLLM 0.11.0 (conda env rsi-vllm11, as the published impact and window arms), tensor parallel 2 with
  NCCL all-reduce (vLLM's custom all-reduce kernel fails on these PCIe A800s, dev record), prefix caching, bf16,
  `b30b_gen.py --mode think32k`.
- **Positions:** Qwen3's config allows 40,960 positions (32,768 output + 8,192 prompt). The prompts have up to 10,346
  tokens, so a run near the budget can pass 40,960. No YaRN (Qwen advises against it when the average context stays
  below 32,768, as it does here); the rotary cache is sized to 49,152 (`hf_overrides`), i.e. plain RoPE as HF
  computes it. Every record stores the last position reached; runs past 40,960 are counted, and a sensitivity
  analysis scores them both ways.
- **Replicates.** R1 (seed 0) on all 1,104 questions is the registered arm. R2 (seed 1) on all 1,104 runs if the
  GPU-hour ledger after R1 and part (b) at 128k stays at or below 55 GPU-hours (so that R2 fits under the cap); it
  gives the seed-to-seed spread and the two-sample mean (reported, not a bar).

### Comparisons, intervals and readings

10,000 resamples, numpy default_rng(0), pooled ratio; `cluster_bootstrap.cl_boot` verbatim), the scenario-stratified
interval beside it.
- **D1 = S32 R1 - published** (decoding and budget). Reading A1: **"the baseline was handicapped"** if D1 >= 0.05 and

- **D2 = system - S32 R1** (the headline under recommended decoding). Reading A2: **"system ahead by >= 0.20"** if the
  lower bound is >= 0.20; "system ahead" if it is > 0; "Qwen3-32B ahead" if the upper bound is < 0; otherwise "tie".
- **Impact without the 80 ambiguous home questions** ("Which of Grandpa's things have to be moved out of it?", read by

- Reported, not bars: D1e = S32 R1 - G-E (pure decoding effect, same engine); G-E - published (engine); R2 rows;
  strict scores; reasoning lengths, runs forced, runs continued, runs past 40,960.

### What the paper may say (decided now)
- On every set, Table 1's Qwen3-32B entry becomes the S32 R1 number if A1 reads "handicap material" there, and the
  text names the decoding ("Qwen3's recommended thinking-mode sampling, 32,768-token reasoning budget"); otherwise
  both numbers may be given, and the text says the recommended decoding does not change the comparison.
- "Our system beats Qwen3-32B reading the whole log" stays only on the sets where A2 reads "system ahead" (or by
  >= 0.20); on a set reading "tie" or "Qwen3-32B ahead" it is withdrawn there.
- The impact comparison is also stated on the 150 unambiguous questions (A3).

## Part (b): BABILong, the same reader's events as a notepad

### The reader re-run and its gate
- **Reader:** the B18 reader: Qwen3-1.7B (rev 70d244cc…) + LoRA `b18_models/student_s0` (adapter sha256 a0a85a62…,
  copied from PACE), merged on the GPU exactly as `b14.Reader` merges it (`b30b_merge.py`), compact prompt
  (`Context: <3 sentences>\nSentence: <s>\nEvents:`), chat template, thinking off, greedy, 200 tokens; B18's parser,
  grounding rule and memory (`b30b_frozen/b18.py`, verbatim).
- **Engine:** vLLM 0.11 on the merged checkpoint (`b30b_gen.py --mode reader`), not HF generate (B18 ran HF generate on
  an H200). The dev engine check below compares the two on training-split prompts.
- **Exact shortcuts.** (1) Only sentences that contain a cue word of some event type are read: `b18.grounded` drops
  every event whose type has no cue word in the sentence (B18 amendment 2), so such a sentence contributes no event
  whatever the reader writes. (2) A prompt depends only on the text, so identical prompts are read once. Counted on the
  test inputs with no model (`b30b_bab.py size`): 128k 2,206,679 sentences, 654,152 with a cue word, 108,283 distinct
  prompts; 512k 2,177,902 / 621,183 / 92,520; 1M 4,165,194 / 1,204,178 / 97,224 (the haystacks repeat across tasks
  and samples). One reader pass reads the union of the three lengths' distinct prompts.
- **Samples:** the B18 test samples: RMT-team/babilong `data/qa{1..5}/{length}.json`, the first 100 per task at 128k and
  the first 25 per task at 512k and 1M.
- **Replay** (`b30b_bab.py assemble`): per sample, in sentence order, every grounded event goes to `b18.World.apply`;
  the events it accepts are kept, in order, with their sentence index; the memory answers with `World.answer`.
- **Gate G-B (per length):** the memory's answer equals the banked B18 answer (`b23_ref/b18_s0` at 128k;
  `b30b_ref/b18_s0` at 512k / 1M, copied from PACE) on >= 99% of the samples, and the QA1-5 accuracy is within 1.0
  point of the banked one (99.8 at 128k; 100.0 at 512k and 1M). If G-B fails at a length, the notepad comparison there
  is still made on the re-run events (paired by construction, so it stays valid) but is labelled and not linked to
  the published B18 number.

### The notepad arm
- **Notepad:** every event the memory accepted, in reading order, one per line, written as plain English
  (`b30b_bab.render`; names as the reader wrote them, lower case, first letter capitalised):
  go "X went to the P." / take "X took the O." / drop "X dropped the O." / give "X gave the O to Y." /
  not_at "X is no longer in the P." / either "X is either in the P or the Q." / rel "The A is D of the B.".
  An empty notepad is the line "(no events)".
- **Prompt:** the line `The text has been replaced by the events read from it, one per line, in reading order.`, the
  notepad, then the direct-answer question of B18's Qwen3 and frontier references and of B23, verbatim
  (`b18_llm.prep`): "Answer the question about the people and objects in the text above. Question: ... Give only the
  answer: a single word (...), or a comma-separated list for 'what is ... carrying' (or 'nothing')."
- **Answerers (nothing trained):** Qwen3-8B (rev b968826d…; primary larger answerer); Qwen3-1.7B (the reader's base
  weights, rev 70d244cc…; primary small answerer); the reader itself (1.7B + LoRA, merged; secondary small answerer).
- **Decoding:** T = thinking on, Qwen3's recommended sampling, 32,768-token reasoning budget, continuation and forcing
  as in part (a) (`b30b_gen.py --mode think32k`; primary); N = thinking off, greedy, at most 64 tokens (B24 arm F's
  decoding; secondary). Arms: q8T, q17T, rdT, q8N, q17N, rdN.
- **Scoring:** `b18.correct_official` on the whole answer (the text after `</think>`, or the forced answer; for N the
  output), with the training-split labels (`b23_data/labels.json`): the rule of B18's frontier references and of B23.
  Second scorer: the verbatim official `compare_answers`. The memory: `b18.correct_official(World.answer(...))`, as B18.

### Comparisons and readings
Paired by sample, QA1-5 pooled (n = 500 at 128k; 125 at 512k and 1M): d = memory - arm in points, discordant pairs,
exact two-sided McNemar p, Wilson intervals, per task.
- Per arm: **"memory adds"** if d >= 1.0 and p < 0.05; **"notepad better"** if d < 0 and p < 0.05; otherwise
  **"not distinguishable"**.
- **NB1 (primary): q8T at 128k.  NB2 (primary): q17T at 128k.**
- **Conservative rule (fixed now, favours the baseline):** for a model size, "the rules and memory add beyond the same
  events given as text" may be said only if every arm of that size reads "memory adds" (8B: q8T, q8N; 1.7B: q17T,
  q17N, rdT, rdN), i.e. against the best notepad arm of that size.
- **NB3 (secondary):** the same at 512k and 1M, where run.

### What the paper may say (decided now)
- If the conservative rule reads "memory adds" for 8B and 1.7B at 128k: given the very events our reader extracted,
  Qwen3-8B / Qwen3-1.7B answering from a notepad score X / Y against the memory's Z, so the rules and the memory, not
  only the extraction, carry the BABILong result (with the per-task gaps).
- If an arm reads "not distinguishable" or "notepad better" for a size: at that size the extraction carries the result
  at 128k, and the memory's contribution there is not accuracy (it is cost, a fixed-size state, and lengths beyond the
  model's window); the BABILong claim is restated accordingly.
- Either way, the B23 sentence ("same 1.7B without the memory") stays, and the notepad row is added beside it as the
  decomposition the referee asked for.

## Verification
- **Second angle** (`b30b_check.py`): logs: every S32 accuracy recomputed with gold from a different derivation
  (impact `nsr1_catalog.answer` on the true state; window `nsr3_questions.union_answer` over `truth_states`; location
  the stored answer, own comparison), must agree exactly; plus an independent lenient parse of the raw model text,
  reported. BABILong: the memory's answers re-derived by a plain-dict tracker of the event semantics written in
  `b30b_check.py` (no vectors), every arm rescored by the official `compare_answers`, the means recomputed from the
  scored files.
- **Hand-reading:** logs: up to 20 questions per set on which S32 R1 and the published run disagree, classified (what
  the extra reasoning bought or lost); BABILong: every 128k sample on which the memory and q8T disagree (up to 30) and
  up to 15 for q17T, classified (notepad reasoning error, event missing, extra event, answer format).
- **Literature** after the verdict: Qwen3's decoding and thinking-budget guidance and test-time scaling of reasoning
  length; facts-in-context versus structured memory (RULER-style arms, entity / state tracking with extracted facts,
  LLM + symbolic memory on bAbI); recorded as supports / conflicts / no precedent in results/b30b_literature.txt.

## Compute
A800 box only: idle GPUs (< 500 MiB and no process, re-checked after 20 s), never GPU 3, never another user's process;
`b30b_run.sh` locks a GPU in B29's claim directory so that the two sessions never share one, and writes the ledger
(`logs/gpu_ledger.txt` on the box, copied to `b30b_out/gpu_ledger.txt`). PACE is not used (its queue is estimated at
days and it has no vLLM). **Cap 80 A800 GPU-hours, dev and smoke runs included.** Estimates (from the dev record):
G-E impact + window ~4, S32 R1 ~10-14, the reader pass (all three lengths) < 0.5, notepad answering ~1 per length,
G-E location ~3, S32 R2 ~10-14. Part (a) runs on pairs of GPUs and part (b) on single GPUs, side by side (scripts
`b30b_run_a.sh`, `b30b_run_b.sh`). Order within part (a): G-E (impact, window) -> S32 R1 -> G-E location -> S32 R2 (if
the ledger allows); within part (b): reader -> 128k arms -> 512k arms -> 1M arms. If the cap binds, S32 R2 is dropped
first, then G-E location, then the 1M and 512k notepad arms.
